# 문서 3층과 참조 경로

[구조·구현 분리 원칙 §2·§3](PRINCIPLES-structure-vs-implementation.md)을 그대로 따른다. 아래는 문서의 소유 위치이며 새로운 구조 계약이나 설정 계층이 아니다.

| 층 | 정본 | 담는 것 |
|---|---|---|
| 체인 템플릿 | [SUPERVISOR](../SUPERVISOR.md), [ROLES](../ROLES.md), 기존 구조 계약 | 프로젝트 비종속 역할·경중·지시서·dispatch·이벤트 |
| 프로젝트 | `projects/<프로젝트>.md` | 프로젝트별 체인 조율, 배포·검증 기본, 편성 예외, 운영·외부 시스템 경계. 기존 프로젝트 문서는 세부 계약·현재 상태의 근거로 연결 |
| 개인 메모리 | 감독자의 MEMORY 색인 및 선호 메모 | 사용자 선호·교정과 위 정본 링크. 실행 절차 복제 없음 |

프로젝트별 문서 main/app/live가 갈라진 현재 사례에서는 **체인 저장소의 projects 아래 프로젝트당 한 파일**이 가장 단순하다. 프로젝트명·경로·도메인 내용은 이 디렉터리에만 둔다. 템플릿 본문에는 넣지 않는다. 기존 구조/구현 연구 보고서의 프로젝트 사례는 역사 자료다.

## 세션과 지시서 연결

1. 브리프 생성 원본(`bootstrap-v2.sh`, `bin/session-init.sh`; v1 `bootstrap.sh`)은 SUPERVISOR와 이 문서를 가리킨다. 자동화는 **경로 전달**이며 문서 내용을 자동 열람한 것으로 취급하지 않는다.
2. 기존 인스턴스의 `PROJECT_DIR`은 워커 작업 위치, `HANDOFF_FILE`은 인계 진입점이다. 인계 진입점에 `projects/README.md` 또는 해당 프로젝트 지침 링크를 둔다. 상대 HANDOFF 경로는 PROJECT_DIR 기준이다. 새 `PROJECT_GUIDE` 변수는 만들지 않는다.
3. 겸용 세션은 세션명이나 cwd만으로 프로젝트를 고정하지 않는다. 인계 진입점의 선택표에서 **사용자가 요청한 대상**을 고른다. 실제 편집 대상·워커 위치가 맞는지 확인하며 세션/런타임의 조작 방식은 usage를 따른다.
4. 작업 지시서는 “`ROLES.md` 및 프로젝트 지침 `<선택한 절대경로>`를 읽고 적용” 한 줄이면 된다. 작업 관련 계약 경로만 더한다. 필수 필드·안전·배포 명령을 반복하지 않는다.

## 설정과 적용 시점

`config.env.example`은 배포 가능한 템플릿 기본값, 로컬 `config.env`는 공통 설정, `instances/<id>.env`는 인스턴스 오버라이드다. 이는 문서 3층과 구별한다. 로더와 환경 우선순위는 [usage §2](../.llmwiki/usage.md)에 둔다. AGY_TIER/AGY_EFFORT/AGY_MODEL은 모델 구현 선택, ACC_TERM_BACKEND는 터미널, ACC_PROACTIVE_MODE는 능동성 구현 설정이다. 미설정은 기존 기본값을 사용하며 설정 파일이 새 예제를 자동으로 가져오지는 않는다. 사용자 인스턴스 모델 선호를 템플릿 기본값으로 단정하지 않는다.

단발 dispatch·훅은 다음 호출부터, 이벤트 대기자는 다음 훅 회전부터, 상주 watchdog·감독자·워커의 기동 설정/브리프는 해당 프로세스 재기동 때 적용된다. 실행 중 세션을 문서 정리 때문에 재시작하지 않는다.
